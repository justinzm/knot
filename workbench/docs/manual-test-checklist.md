# Knot Workbench 手动测试清单

## 1. 启动与外观

- 启动 `pnpm tauri dev`
- 确认窗口标题为 `Knot Workbench`
- 确认默认主题为暗色
- 切换到浅色主题后，左侧导航、顶部状态栏、右侧检查器仍可读
- 确认左侧主导航只有 7 项：总览、准备项目、运行时、工作流、预检、运行、产物

## 2. 项目准备

- 选择一个没有 `knot/` 的普通项目文件夹
- 确认“项目检测”显示缺少 Knot，且可执行“复制 Knot 框架”
- 执行复制后，确认目标目录出现 `knot/core/`、`knot/automation/`、`knot/runtime/`
- 选择一个已有生产运行时的项目，确认弹出保护对话框
- 验证“备份后替换”“原地刷新”“另选目录”三种入口都可点击

## 3. 运行时生成

- 在“准备项目”点击“生成扫描摘要”
- 确认扫描摘要显示包含目录、排除目录、识别文件和目标文件
- 点击“生成运行时草案”
- 确认“生成日志”显示实时 stdout/stderr
- 成功后确认显示暂存区路径与生成文件列表

## 4. 运行时编辑与保存

- 打开“运行时”页面，修改简报和项目规格字段
- 打开“工作流”页面，修改内容单元标题、输出和依赖
- 构造非法路径（如 `../bad.md`），确认“校验并保存”报错
- 修正后再次保存，确认 `knot/runtime/project-brief.md`、`project-spec.json`、`taskboard.json` 已更新
- 若已存在旧文件，确认 `knot/runtime/archive/workbench-save-*` 快照被创建

## 5. 预检与运行

- 进入“预检”页面执行预检
- 确认显示检查项、日志和预检报告
- 预检失败时，确认“开始运行”按钮不可用
- 预检通过后，进入“运行”页面启动 Knot 循环
- 确认实时日志持续刷新，停止按钮可终止进程
- 若输出 `<promise>COMPLETE</promise>`，确认状态显示“已完成”

## 6. 产物浏览

- 进入“产物”页面
- 检查“产物”“审核”“进度”三个标签能切换
- 选择 Markdown、JSON、TXT 文件，确认预览区域正常滚动
- 检查 `progress.txt` 时间线是否按记录顺序展示

## 7. 回归

- 关闭应用重新打开
- 确认最近项目、主题、默认 CLI、最大迭代次数仍保留
- 再次进入“准备项目”，确认项目名、路径和运行时状态正确回显
